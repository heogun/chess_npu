# DE1-SoC F2SDRAM·CSR 측정

수행일: 2026-11-06. **실제 DE1-SoC에서 FPGA→SDRAM 포트와 경량 HPS→FPGA 브리지를 잰 결과다.** NNUE 가속기는 아직 없고, 측정 전용 블록 `mem_probe`를 썼다. ARM-only 대 ARM+FPGA 비교는 아직 하지 않았다.

## 판정

- **정확성: PASS.** 256 MiB 창을 쓴 뒤 순차 검증 읽기 BAD 0, 무작위 검증 읽기(1M 워드) BAD 0. 속도 측정 65개 지점도 모두 검증을 켠 채(쓰기는 같은 패턴 재기록) BAD 0. 두 번 실행했고 두 번 모두 같다.
- **반복성:** 두 실행의 65개 지점 차이는 대역폭 최대 0.3 MB/s, 평균 지연 최대 0.3 ns. CSR 지연 차이는 0.4 ns 이하.
- 실행 횟수는 2회, 보드 1대, 전원 투입 1회 안의 결과다.

## 구성

| 항목 | 내용 |
|---|---|
| FPGA | `hw/quartus/board` (`board.sof`), JTAG로 적재. 타이밍 모든 corner 통과 |
| F2SDRAM | 포트 0, 64비트 Avalon-MM 양방향, 100 MHz. 이론 최대 64 bit × 100 MHz = **800 MB/s** |
| HPS DDR3 | 32비트, 400 MHz(800 MT/s), 이론 최대 3.2 GB/s. 타이밍은 U-Boot qts(CL7) |
| CSR | 경량 HPS→FPGA 브리지 0xFF200000, `/dev/mem` `O_SYNC` 매핑 |
| U-Boot | v2026.07 + [`linux/uboot-de1soc-fpgaportrst.patch`](../../linux/uboot-de1soc-fpgaportrst.patch) (`FPGAPORTRST` 0x0 → 0x111) |
| Linux | 6.12.115, U-Boot에서 수동 부팅, `mem=768M` |
| 측정 창 | 물리 0x30000000–0x3FFFFFFF(256 MiB). `/proc/iomem`의 System RAM은 0x00000000–0x2FFFFFFF |
| 부하 | ARM은 유휴(측정 프로그램만). ARM 메모리 트래픽과의 경합은 재지 않았다 |
| 프로그램 | [`sw/board/probe.c`](../../sw/board/probe.c), 정적 링크 |

## 보드 절차 (이번에 실제로 한 것)

1. 카드 앞 17 MiB(MBR + A2)만 새 SPL/U-Boot로 교체. 쓰기 전에 카드 전체를 백업했다. 읽어 들인 해시 일치, rootfs 시작 부분은 백업과 같다.
2. 전원 → U-Boot 자동 부팅 중단 → PC에서 `quartus_pgm`으로 `board.sof` 적재(device 2, 5CSEMA5). MSEL(SW10)은 건드리지 않았다.
3. U-Boot `bridge enable` 전후 레지스터([로그](logs/board_uboot_bridge_enable.txt)):

   | 레지스터 | 전 | 후 |
   |---|---|---|
   | `SYSMGR.ISWGRP.HANDOFF3` (0xFFD0808C) | 0x111 | |
   | `SDR.FPGAPORTRST` (0xFFC25080) | 0x0 | **0x111** |
   | `RSTMGR.BRGMODRST` (0xFFD0501C) | 0x7 | **0x0** |

   이어서 U-Boot `md`로 ID 0x4D505231 읽기, SCRATCH 쓰기·읽기, 자유 카운터 증가를 확인했다.
4. `load`/`bootz`로 Linux를 `mem=768M`으로 부팅하고 `probe all` 실행. 로그: [1회차](logs/board_probe_run1.txt), [2회차](logs/board_probe_run2.txt).

## CSR (경량 브리지) 왕복 지연

100,000회 평균, ARM `CLOCK_MONOTONIC` 기준, 호스트가 관측한 값.

| 동작 | 지연 |
|---|---|
| 읽기 1회 | **290.4 ns** |
| 쓰기 1회 | 300.5 ns |
| 쓰기 + 읽기 | 591.0 ns |

`/dev/mem` `O_SYNC` 매핑이라 쓰기도 다음 접근 전에 끝난다(완전한 posted write가 아니다). 패브릭 쪽 처리는 1 사이클(10 ns)이므로 나머지는 브리지와 인터커넥트 시간이다. 패브릭 자유 카운터는 ARM 시계 대비 100.000 MHz였다.

| 경우 | 최소 | 평균 | 최대 |
|---|---|---|---|
| 순차, burst 1, 요청 1개 | 130 ns | 134.8 ns | 540 ns |

- 요청 1개일 때 지연 분포(히스토그램 칸 40 ns): 순차는 98.1 %가 120–159 ns, 1.9 %가 360–399 ns다. 무작위는 97.9 %가 120–199 ns, 2.1 %가 320–559 ns다. 긴 쪽은 DRAM 행 전환이나 refresh일 수 있지만 원인은 확인하지 않았다.
- 포화 상태에서는 요청 16개와 32개의 평균 지연이 같고(burst 16에서 1865 ns), waitrequest 사이클이 약 790만으로 크다. 포트가 일정 수 이상의 요청을 받지 않고 막는다는 뜻이다. 그 상한이 몇 개인지는 재지 않았다.

## 해석 (측정 범위 안에서)

- **800 MB/s는 DDR의 한계가 아니라 이 구성의 FPGA 쪽 한계(64비트 × 100 MHz)다.** burst 4 이상 쓰기, burst × 동시 요청이 대략 32 beat 이상인 읽기는 모두 이 값에 닿았다. DDR3가 낼 수 있는 최대(이론 3.2 GB/s)는 이 측정으로 알 수 없다. 알려면 클럭을 올리거나 포트를 넓혀야 한다.
- 대역폭을 다 쓰려면 약 135 ns × 800 MB/s ≈ 108 byte(≈ 14 워드) 이상이 동시에 진행 중이어야 한다. burst 1 순차 읽기가 요청 8개에서 439 MB/s, 16개에서 765 MB/s인 것과 맞는다.
- 단어(8 byte) 단위 무작위 읽기는 요청을 늘려도 **445 MB/s(약 5,560만 워드/s)**에서 멈춘다. burst 2 이상이면 765 MB/s 이상이다. 흩어진 8 byte 읽기는 연속 읽기의 약 56 %까지만 나온다.
- 지연이 긴 꼬리(수백 ns)는 드물지만(약 2 %) 있다. 요청 하나씩 기다리는 구조라면 평균에 반영된다.
- CSR 왕복은 약 0.3 µs다. 평가 1회마다 CSR을 여러 번 왕복하는 구조라면 이 시간이 그대로 쌓인다. 실제 평가 지연은 가속기 구조가 정해진 뒤 따로 재야 한다.

## 제한

- ARM 쪽 메모리 트래픽이 없는 상태다. Stockfish가 돌면서 DDR을 같이 쓰면 값이 달라질 수 있다.
- DDR3 타이밍은 U-Boot qts 값(CL7)이다. Quartus 쪽 HPS 파라미터(CL11)와 다르다.
- FPGA는 JTAG로 올렸다. 카드에서 `fpga load`로 올리는 경로는 시험하지 않았다(MSEL 변경 필요).
- 한 포트, 64비트, 100 MHz 구성의 결과다. 다른 폭, 포트 수, 클럭에는 그대로 적용하지 않는다.
- 측정 블록과 측정 프로그램은 이 프로젝트에서 만든 것이다. 그 정확성 근거는 Verilator 정확 일치 검사와 보드의 BAD 0, 클럭 대조뿐이다.
