# ARM 프로파일: 무엇을 가속할 것인가

수행일: 2026-11-05. **에뮬레이터 측정과 비용 모델 추정이며, DE1-SoC 측정이 아니다.** 명령어 수는 이 바이너리에 대해 정확하고, 시간은 모두 가정에 기반한 추정이다.

## 결론

1. **탐색을 FPGA로 옮길 이유가 없다.** NNUE 외 전부를 합쳐도 ARM 시간의 약 16%(명령어 기준 25%)로 추정된다. 전부 공짜로 만들어도 전체 속도 향상은 최대 약 1.2~1.3배다.
2. **가속 대상은 NNUE가 맞다.** 시간의 약 83~85%, 명령어의 75%다. NNUE 시간이 0이 되어도 상한은 4~6.7배다.
3. **현재 RTL은 ARM보다 확실히 빠르다고 말할 수 없다.** 지연 없는 메모리를 가정해도 평가당 시간이 ARM 추정치와 비슷한 수준이고, 실제 DDR 지연은 아직 빠져 있다.

## 전체 속도 향상의 상한

X를 NNUE 시간 비중, A를 NNUE 가속비라 하면 전체 속도 향상은 `1 / (1 - X + X/A)`이다.

| X | A=1 | A=1.5 | A=2 | A=3 | A=5 | A=10 | A=∞ |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 75% | 1.00 | 1.33 | 1.60 | 2.00 | 2.50 | 3.08 | 4.00 |
| 82% | 1.00 | 1.38 | 1.69 | 2.21 | 2.91 | 3.82 | 5.56 |
| 85% | 1.00 | 1.40 | 1.74 | 2.31 | 3.12 | 4.26 | 6.67 |

## 현재 RTL과 ARM의 평가당 시간

| 경로 | 조건 | 평가당 시간 |
|---|---|---|
| ARM NNUE 전체 | 추정 평균, 925 MHz, 저·중·고 | 90 / 155 / 229 µs |
| ARM 누산기 | 추정 평균, 저·중·고 | 57 / 102 / 155 µs |
| ARM FC 층 | 추정 평균, 저·중·고 | 31 / 50 / 69 µs |
| FPGA 전체 | 탐색 trace 중앙값, 100 MHz, 이상적 메모리 | 82 µs |
| FPGA 양 관점 증분 | 위와 같음 | 72 µs |
| FPGA 양 관점 refresh | 위와 같음 | 178 µs |
| FPGA 재사용 (FT+FC만) | 위와 같음 | 29 µs |

ARM의 값은 평균 추정이고 FPGA의 값은 중앙값이어서 직접 비교할 수 있는 수치가 아니다. FPGA 값에는 실제 DDR 지연, HPS 통신, 동기화, 결과 회수가 빠져 있다. ARM 클럭 925 MHz도 실제 보드 설정으로 확인해야 한다. 따라서 **현 상태의 A는 1 근처로 봐야 하며, 1 미만일 수도 있다.**

## 읽어낸 내용

- **FC 층이 ARM에서 유독 비싸다.** 공식 희소 입력 경로는 SSSE3, LSX, LASX, `USE_NEON >= 8`에서만 켜지므로(`layers/affine_transform_sparse_input.h`), ARMv7은 FC0를 입력 1024개 전체에 대해 계산한다. `vmull_s8`과 `vmlal_s8`만으로 명령어의 26%다. 희소 처리하는 FPGA에 유리한 지점이다.
- **누산기는 연산보다 메모리가 문제다.** 명령어는 FC와 비슷한데 L2 miss가 약 20배 많다. FPGA도 같은 DDR에서 읽으므로, 이 부분의 이득은 실제 DDR 대역폭에 달려 있다.
- **x86과는 비중이 다르다.** x86 AVX2 `perf`에서는 NNUE 55%, FC 12.5%다(유효 샘플 약 11,000개). 넓은 SIMD와 희소 경로 덕분으로 보인다. x86 결과로 ARM 비중을 판단하면 안 되며, 이 측정은 보조 자료다.
